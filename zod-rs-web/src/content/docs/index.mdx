## Quick example

```rust
use serde_json::json;
use zod_rs::prelude::*;

fn main() {
    let schema = object()
        .field("name", string().min(2).max(50))
        .field("email", string().email())
        .field("age", number().min(0.0).max(120.0).int());

    let data = json!({
        "name": "Alice",
        "email": "alice@example.com",
        "age": 25
    });

    match schema.safe_parse(&data) {
        Ok(value) => println!("Valid: {:?}", value),
        Err(errors) => println!("Invalid: {}", errors),
    }
}
```

## What is zod-rs?

**zod-rs is a Rust validation library** that validates data at runtime using composable schemas. You define rules with primitives like `string()`, `number()`, `object()`, and `array()`, compose them into complex schemas, and call `safe_parse()` to validate input — getting back either a typed struct or detailed errors with the full path to each failing field (e.g. `user.addresses[0].zip`).

### How Rust validation works with zod-rs

1. **Define a schema** — use builder methods (`string().email().min(5)`) or derive it from a struct with `#[derive(ZodSchema)]`
2. **Validate input** — call `safe_parse(&json_value)` or `validate_and_parse(&json_value)` to validate and deserialize in one step
3. **Handle errors** — every error includes the full field path, a human-readable message, and i18n support

Unlike attribute-only validators such as [validator](https://crates.io/crates/validator) and [garde](https://crates.io/crates/garde), zod-rs schemas are values: you can build them at runtime, store them, compose them, and reuse them across your codebase. This makes zod-rs ideal for validating [API request bodies](/integrations/axum/), configuration files, webhook payloads, and any untrusted input where the schema may not be known at compile time.

### What makes zod-rs different

- **Validates raw JSON directly** — no need to deserialize first; parsing and validation happen in one step
- **Runtime schema composition** — build, combine, and reuse schemas dynamically, not just at compile time
- **Full-path error messages** — errors report the exact location of failures in nested data (`user.profile.email`)
- **TypeScript codegen** — generate matching [TypeScript Zod schemas](/typescript-codegen/zod-ts/) from Rust types so frontend and backend validate with the same rules
- **Built-in i18n** — [localize error messages](/advanced/i18n/) with built-in locale support
- **Framework integration** — built-in [Axum support](/integrations/axum/) with structured error responses

For a detailed comparison, see [Choosing a Rust Validation Library](/comparison/choosing/) or the migration guides from [validator](/comparison/vs-validator/) and [garde](/comparison/vs-garde/).

## Frequently asked questions

### How is zod-rs different from the validator crate?

The [validator](https://crates.io/crates/validator) crate checks structs you have already deserialized. zod-rs validates raw JSON values directly, so parsing and validation happen in one step, schemas can be built and composed at runtime, and errors carry the full path to the failing field. See the [full comparison and migration guide](/comparison/vs-validator/).

### Does zod-rs work with serde?

Yes. Schemas validate `serde_json::Value`, the derive macro honors `#[serde(rename)]` and `#[serde(rename_all)]`, and [enum validation](/enums/overview/) matches serde's externally tagged JSON format.

### Can I validate HTTP request bodies in Axum?

Yes. Enable the `axum` feature to validate request bodies with a zod-rs schema and return structured validation errors from your handlers. See the [Axum integration guide](/integrations/axum/).

### Can I share validation rules between Rust and TypeScript?

Yes. The `ZodTs` derive macro and the [zod-rs-ts CLI](/typescript-codegen/cli/) generate TypeScript Zod schemas from your Rust types, so the frontend and backend validate with the same rules. See the [fullstack validation guide](/guides/fullstack-validation/).

### How do I validate structs in Rust?

Add `#[derive(ZodSchema)]` to your struct and annotate fields with `#[zod(email)]`, `#[zod(min_length(3))]`, or other validation rules. Then call `validate_and_parse()` to validate JSON input and get a typed struct in one step, with full-path error messages for every failing field. See the [struct validation guide](/guides/validate-structs/) and the [attributes reference](/derive-macros/attributes/).

### What is the best Rust validation library?

It depends on your use case. The [validator](https://crates.io/crates/validator) crate and [garde](https://crates.io/crates/garde) are best for checking structs you have already deserialized. zod-rs is best when validation starts at a boundary — API requests, config files, webhooks — because it validates raw JSON directly, composes schemas at runtime, generates TypeScript Zod schemas, and reports full-path errors. See the [detailed comparison](/comparison/choosing/).
