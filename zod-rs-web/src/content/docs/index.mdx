## Quick example

```rust
use serde_json::json;
use zod_rs::prelude::*;

fn main() {
    let schema = object()
        .field("name", string().min(2).max(50))
        .field("email", string().email())
        .field("age", number().min(0.0).max(120.0).int());

    let data = json!({
        "name": "Alice",
        "email": "alice@example.com",
        "age": 25
    });

    match schema.safe_parse(&data) {
        Ok(value) => println!("Valid: {:?}", value),
        Err(errors) => println!("Invalid: {}", errors),
    }
}
```

## What is zod-rs?

zod-rs is a Rust validation library inspired by [Zod](https://zod.dev) from the TypeScript ecosystem. It validates JSON at runtime — API request bodies, configuration files, webhook payloads, or any untrusted input — against schemas you compose from primitives like `string()`, `number()`, `object()`, and `array()`.

Unlike attribute-only validators, zod-rs schemas are values: you can build them at runtime, store them, compose them, and reuse them across your codebase. Validation and parsing happen in one step, and every error reports the full path to the failing field, such as `user.addresses[0].zip`.

For struct-based workflows, `#[derive(ZodSchema)]` generates the schema from your type definition, honoring serde attributes like `#[serde(rename_all = "camelCase")]`. And with `#[derive(ZodTs)]`, zod-rs generates matching [TypeScript Zod schemas](/typescript-codegen/zod-ts/) so your frontend and backend validate with the same rules.

## Frequently asked questions

### How is zod-rs different from the validator crate?

The [validator](https://crates.io/crates/validator) crate checks structs you have already deserialized. zod-rs validates raw JSON values directly, so parsing and validation happen in one step, schemas can be built and composed at runtime, and errors carry the full path to the failing field. See the [full comparison and migration guide](/comparison/vs-validator/).

### Does zod-rs work with serde?

Yes. Schemas validate `serde_json::Value`, the derive macro honors `#[serde(rename)]` and `#[serde(rename_all)]`, and [enum validation](/enums/overview/) matches serde's externally tagged JSON format.

### Can I validate HTTP request bodies in Axum?

Yes. Enable the `axum` feature to validate request bodies with a zod-rs schema and return structured validation errors from your handlers. See the [Axum integration guide](/integrations/axum/).

### Can I share validation rules between Rust and TypeScript?

Yes. The `ZodTs` derive macro and the [zod-rs-ts CLI](/typescript-codegen/cli/) generate TypeScript Zod schemas from your Rust types, so the frontend and backend validate with the same rules.
